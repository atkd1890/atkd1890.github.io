私の仕事は 4 つの時代を通ってきました。モバイル、インディーゲーム、システム、そして今は AI です。ところが私の GitHub アカウントを開いても、ほとんど何も見えません。仕事の大半は非公開リポジトリや会社のリポジトリにあるか、公開できない契約のもとにあるからです。

よくあるポートフォリオは、公開リポジトリの一覧と数行の説明です。私にはその形が使えません。そこで最初に立てた問いはこうでした。**証拠の大半を見せられないとき、どうすれば実力を伝えられるのか?**

このサイト [atkd1890.github.io](https://atkd1890.github.io) がその答えです。この記事では、その設計を紹介します。

## 要点

- **GitHub がすべての役割を担う**:リポジトリが CMS、API がデータソース、Actions が CI、Pages がホスティング。サーバーもデータベースもありません。
- **設計の段階からプライバシーを守る**:サイトに出るのは宣言したものだけ。非公開プロジェクトはコードネームで表示し、本当のリポジトリ名は Secret に置き、すべてのビルドは公開前に「リークガード」を通ります。
- **リポジトリ一覧ではなく、段階的な証拠**:集計した数字から本物のコードまで。
- **チームのように作る**:ワークフロー 3 本、アーキテクチャ決定記録(ADR)6 件、ユニットテスト 57 件、E2E 64 回分。アクセシビリティとパフォーマンス予算のチェックが、すべてのマージの前に立ちはだかります。
- トップページの JavaScript は約 **3.7 KB**。3 言語、ライト/ダーク、⌘K のコマンドパレット付きです。

## 4 つの原則

コードを書く前に、4 つの原則を決めました。その後のすべての判断は、ここに立ち返ります。

1. **宣言したものだけを表示する。** サイトがリポジトリを勝手に並べることはありません。プロジェクトを載せるには、宣言ファイル `showcase.yml` に追加する必要があります。
2. **非公開プロジェクトはコードネームで。** 本当のリポジトリ名は、サイトにも、この公開リポジトリにも、CI のログにも出てきません。
3. **非公開リポジトリが出すのは数字だけ。** 非公開リポジトリのコードは 1 行も外に出ません。
4. **本物のコードは新しく作ったもの。** 読めるコードは、最初から公開前提で作ったものです。切り出したライブラリ、小さなツール、そしてこのサイト自身のリポジトリ。

## 段階的な証拠

リポジトリの一覧の代わりに、各プロジェクトを「証拠の段階」で見せます。弱いものから強いものへ:

| 段階                           | 形                                               | 見せるもの             |
| ------------------------------ | ------------------------------------------------ | ---------------------- |
| シグナル                       | 言語、年ごとのコントリビューション、ヒートマップ | 数字だけ               |
| プロジェクトカード             | コードネーム、時代、分野、役割、技術、年         | 承認したメタデータ     |
| ケーススタディ、ポストモーテム | 背景、制約、アーキテクチャ、判断、数字で示す結果 | 考え方(コードではない) |
| 抜粋                           | パターンを示すために書き直した短いコード         | 技術(知的財産ではない) |
| デモ                           | 動画、遊べるビルド                               | 製品(ソースではない)   |
| オープンソース、ツール         | 切り出したライブラリ、単一 HTML のツール         | 本物のコード           |

クライアント向けの受託プロジェクトなら、カードの段階で止めることもあります。分野、規模、役割まで。すべてのリポジトリで共有しているデザインシステムなら、ケーススタディまで進められます。段階が上がるごとに少しずつ多くを見せ、どこまで見せるかはプロジェクトごとに選びます。

## GitHub がすべての役割を担う

サイト全体が、GitHub にもともとあるものだけで動いています。自分で運用するものはありません。

{% diagram "blog/2026/github-native-portfolio/architecture.ja", "アーキテクチャ:Issue と PR が CMS、Actions がチェックとビルド、API が数字を提供し、Pages がサイトを配信" %}

- **CMS はリポジトリ。** 記事のアイデアは Issue、下書きは Pull Request、マージが公開です。コンテンツの変更はすべてレビューできる差分になります。
- **データソースは GitHub API。** 1 日 1 回、Actions が GraphQL で数字を読み、サイトを作り直します。誰もボタンを押さなくても、トップページの数字は常に最新です。
- **CI は Actions。** すべての Pull Request は、フォーマット、型、ユニットテスト、E2E、アクセシビリティ、パフォーマンス予算、Secret のスキャン、そしてリークガードを通過しなければなりません。
- **ホスティングは Pages。** `gh-pages` ブランチではなく、Actions からデプロイします。

ジェネレーターは [Eleventy](https://www.11ty.dev/)、テンプレートは Nunjucks、CSS は素のままです。UI フレームワークは使わず、JavaScript は操作が必要な場所にだけ、使うページでだけ読み込みます。

## 設計の段階からプライバシーを守る

ここがシステム全体でいちばん大事な部分です。非公開リポジトリのデータは、HTML に届くまでにいくつもの層を通ります。

{% diagram "blog/2026/github-native-portfolio/privacy.ja", "非公開データの流れ:メタデータだけを取得し、コードネーム単位でまとめ、許可リストとリークガードを通してからデプロイ" %}

### コードネームと、Secret に置いた本当の名前

プロジェクトの宣言ファイルは公開リポジトリにあります。そこに本当のリポジトリ名が書かれていたら、それ自体が漏洩です。そこで `repo` フィールドには 2 つの値しか入れられません。

```yaml
- codename: signal-desk
  repo: '@secret' # または null。本当の名前は決して書かない。
  era: ai
  domain: 個人資産向けのシグナルボット
  evidence: [card, case-study]
```

コードネームと本当のリポジトリの対応表は GitHub の Secret に置いています。スキーマの検証はそれ以外の値を拒否するので、うっかり本当の名前を書けば、その場でビルドが失敗します。

### メタデータしか読めないトークン

非公開リポジトリから数字を読むために、サイトにはトークンが必要です。このトークンの権限は **Metadata: read-only** だけ。リポジトリ名、言語、作成日、最終 push 日は見えますが、**コードは 1 行も読めません**。年ごとのコントリビューションは、非公開の仕事も数字として数えてくれる公開のコントリビューションカレンダーから取ります。

その代わり、プロジェクトごとのコミット数は数えられません。それで構わないと判断しました。万一トークンが漏れても、失うのは名前の一覧であって、ソースコードではないからです。

### テンプレートの前に許可リスト

API から来るデータはすべて `whitelist()` 関数を通り、許可したフィールドだけでデータを組み立て直します。数字はテンプレートに渡る前にコードネーム単位にまとめます。API の応答に想定外のフィールドが紛れ込んでも、その先には進めません。

### リークガード

最後の層は、出力そのものに対して動きます。ビルドした HTML のすべて、Pull Request で変わった Markdown、そしてコミットの作者情報まで。止めるのは次のものです。

- **非公開リポジトリの名前**。単語単位で照合するので、文章中のありふれた単語を誤って止めることはありません。
- **禁止リスト**(勤務先、クライアント、個人の連絡先)。大文字小文字を区別せず、**ベトナム語の声調記号も区別しません**。"Nguyễn" と "nguyen" は同じものとして扱います。
- 画像の **EXIF**。写真には GPS の位置情報が入っていることがあります。
- GitHub の noreply アドレスではない**コミット作者のメールアドレス**。

禁止リストは Secret に置いてあり、何かを止めたときに出力するのはファイル名、行番号、ルール番号だけ。**一致した値そのものは決して出力しません。** 公開リポジトリの CI ログは誰でも読めるからです。さらに CI が動くたびに、使い捨てのビルドに「カナリア」文字列を仕込み、まだ確実に止められることを確かめます。

## 何も漏らさずに数字を見せる

トップページの「数字で見る」には数字しかありません。直近 12 か月のコントリビューション、活動日数、掲載プロジェクトの言語の内訳、52 週分のヒートマップ。どのグラフにも、スクリーンリーダー向けの文章の説明が付いています。

トークンがないとき(たとえばフォークからの Pull Request)は、集計値だけのスナップショットでビルドし、ページには「デモデータ」と表示します。データがなくてもサイトは落ちません。

## 細部へのこだわり

エンジニアのポートフォリオは、製品と同じ丁寧さで作るべきだと考えています。いくつか紹介します。

- **「ターミナル」デザイン**。ハブサイト [atkd1890.me](https://atkd1890.me) の Coding ペルソナとトークンの段階で揃えています。色、JetBrains Mono フォント、角のない四角、そしてどのブロックもコマンドの 1 行から始まります。
- **⌘K のコマンドパレット**でどこへでも移動でき、`g h`、`g b`、`?` のショートカットもあります。ゲーム風の効果音もありますが、初期状態はオフです。
- **3 言語**:ベトナム語が既定、英語は `/en/`、日本語は `/ja/`。言語の切り替えは、JavaScript をオフにしていても、同じページの別言語版へ移動します。
- **アクセシビリティは自動でチェック**:axe がすべてのページをライト/ダークの両方で検査し、テストが色のトークンを読んで、文字と背景のすべての組み合わせが WCAG AA のコントラストを満たすか確かめます。
- **軽さ**:トップページの JavaScript は圧縮後で約 3.7 KB、CSS は 6 KB 未満、Web フォントは自前ホストの 1 つだけ。この予算は CI が守らせます。

## ひとりでも、チームのように

このサイトは、ひとりの人間がコードだけでなくすべての役割をこなせることを示すために作っています。そのためロードマップの各タスクには役割(デザイン、エンジニアリング、DevOps、QA、セキュリティ、マーケティング、PM)のタグを付け、役割ごとに「完了の定義」を決めています。

具体的には、`main` ブランチは保護されています。すべての変更は Pull Request を通り、チェックがすべて成功したときだけマージできます。長く影響する判断はすべて ADR に残しています。なぜ GitHub だけで作るのか、なぜリポジトリ名を Secret に置くのか、なぜリークガードを必須にしたのか、なぜトークンはメタデータしか読めないのか、プライバシーの水準、そして 3 言語対応。リポジトリは公開なので、すべて誰でも読めます。

## AI と一緒に作る

このサイトのコードとドキュメントの大部分は Claude Code と一緒に作りました。役割ははっきり分けています。エージェントが提案して実装し、人間が判断してレビューする。プライバシーの判断、何を見せるか、文章のトーンは、常に人間が決めます。

その境界はルールとして書いてあります。サイトは AI モデルを一切呼ばず、エージェントの Secret も持ちません。今後作るブログ用のエージェントは別の非公開リポジトリに置き、Pull Request を開くことしか許されません。ほかのすべての変更と同じチェックを通ります。エージェントが下書きした記事には、この記事と同じように、冒頭に「AI 支援」のラベルが付きます。

## これから

- **最初のケーススタディ**。背景、制約、アーキテクチャ、判断、結果、学びの枠組みで書きます。
- **ブログ用のエージェント**。TIL、おすすめのリンク、毎週のビルドログを、それぞれレビュー待ちの Pull Request として出します。
- **ベンチマークのシリーズ**。新しい AI モデルが出るたびに、同じ仕様で同じ小さなゲームのプロトタイプを作らせ、同じ基準で採点します。
